## Erledigt
- [Hoch] Inkonsistente Filter-Trefferzahlen bei Programm-Filtern (156/30/416 bei "Kraft - Wenig Zeit") — Root Cause: `useWods.ts` racet die Supabase-Query gegen ein 5s-Timeout; verliert die Query, fiel der Code still auf den lokalen `wods.json`-Fallback zurück, der `wodCategory` komplett ignoriert (diese WODs existieren nur in Supabase) → mal korrekte, mal stark abweichende Zahl. Fix: Timeout auf 8s angehoben; bei `forceSupabase`-Filtern (wodCategory/editorsPick) wirft die Query jetzt bei Timeout/Fehler einen Error statt still auf falsche lokale Daten umzuschalten — `WodList` zeigt dafür den vorhandenen Fehlerzustand ("WODs konnten nicht geladen werden"). Verifiziert: 3× Reload mit identischem Filter → konsistent "30 Workouts", kein Fallback mehr. **Der ursprünglich mitgemeldete Main-Thread-Freeze (Symptom 1, CDP "renderer unresponsive") konnte auf `carveout.app` NICHT reproduziert werden** (WOD-Detail lädt in ~2s normale Netzwerk-Ladezeit) — vermutlich ein Artefakt der Test-Infrastruktur der ursprünglichen Chrome-Test-Session, nicht ein echter App-Bug. Falls der Freeze mit konkreten Repro-Schritten wieder auftritt, neu aufnehmen.
